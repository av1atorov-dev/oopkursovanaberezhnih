# PrisonApp - детальна документація з роботи програми

## 1. Призначення програми

`PrisonApp` - це настільний застосунок для ведення довідника ув'язнених виправного закладу.
Програма призначена для зберігання анкетних даних, швидкого пошуку потрібного запису, фільтрації списку за заданими критеріями та формування статистичних зведень.

Застосунок реалізовано як Windows-програму на:

- `C#`
- `WPF`
- `.NET 10.0`
- патерні `MVVM`
- локальному зберіганні даних у `JSON`

Програма не потребує бази даних і працює з файлом `data.json`, який створюється поруч із виконуваним файлом.

## 2. Основні можливості

Програма підтримує такі функції:

- перегляд списку ув'язнених у головному вікні;
- додавання нового запису;
- редагування наявного запису;
- видалення запису з підтвердженням;
- пошук за прізвищем, ім'ям, по батькові та статтею;
- фільтрація за камерою, місцем в ієрархії та діапазоном дат звільнення;
- автоматичний розрахунок дати звільнення;
- підтримка ознаки `Довічно`;
- перегляд статистики щодо складу контингенту;
- автоматичне збереження змін у `data.json`.

## 3. Запуск програми

### 3.1. Готовий виконуваний файл

Зібраний файл застосунку знаходиться за шляхом:

`PrisonApp/bin/Debug/net10.0-windows/PrisonApp.exe`

Для запуску достатньо:

1. відкрити папку `bin/Debug/net10.0-windows`;
2. двічі клацнути по файлу `PrisonApp.exe`.

### 3.2. Запуск із середовища розробки або термінала

Якщо проєкт відкрито у Visual Studio, його можна запустити кнопкою `Start`.

Якщо запускати з термінала:

1. відкрити термінал у папці проєкту;
2. виконати команду:

```powershell
dotnet run
```

## 4. Поведінка під час першого запуску

Під час першого запуску застосунок перевіряє наявність файлу `data.json` поруч із `.exe`.

Якщо файл відсутній:

- програма автоматично створює `data.json`;
- у файл записуються 3 демонстраційні записи;
- ці записи одразу відображаються у головному вікні.

Якщо файл вже існує, програма завантажує дані з нього.

## 5. Структура інтерфейсу

Програма складається з трьох основних вікон:

1. головне вікно;
2. вікно додавання або редагування ув'язненого;
3. вікно статистики.

## 6. Головне вікно

Головне вікно є центральною частиною застосунку. У ньому користувач працює зі списком ув'язнених і отримує доступ до всіх функцій.

### 6.1. Склад головного вікна

Головне вікно містить:

- рядок меню;
- панель інструментів;
- панель пошуку та фільтрів;
- таблицю зі списком ув'язнених;
- рядок стану з кількістю відображених записів.

### 6.2. Рядок меню

У меню доступні розділи:

- `Файл`
- `Записи`
- `Статистика`
- `Довідка`

За їх допомогою можна:

- закрити програму;
- додати, редагувати або видалити запис;
- відкрити вікно статистики;
- переглянути коротку інформацію про програму.

### 6.3. Панель інструментів

Панель інструментів містить кнопки:

- `Додати`
- `Редагувати`
- `Видалити`
- `Статистика`

Ці кнопки дублюють основні дії з меню та пришвидшують роботу.

### 6.4. Таблиця ув'язнених

Таблиця відображає список записів і містить такі стовпці:

- `№`
- `Прізвище, ім'я, по батькові`
- `Дата народження`
- `Стаття КК`
- `Термін`
- `Дата взяття під варту`
- `Дата звільнення`
- `Камера`
- `Ієрархія`

### 6.5. Сортування

Користувач може сортувати таблицю натисканням на заголовок стовпця.
Після сортування номери рядків перераховуються автоматично.

### 6.6. Гарячі клавіші

Підтримуються такі клавіші:

- `Ctrl+N` - відкрити вікно додавання нового запису;
- `Delete` - видалити вибраний запис;
- подвійне клацання по рядку - відкрити редагування.

## 7. Пошук і фільтрація

У верхній частині головного вікна розташована панель пошуку та фільтрів.

### 7.1. Поле `Пошук`

Це поле виконує пошук у реальному часі за такими полями:

- прізвище;
- ім'я;
- по батькові;
- стаття КК.

Пошук:

- нечутливий до регістру;
- починає працювати одразу під час введення тексту;
- не потребує окремого підтвердження.

### 7.2. Фільтр `Камера`

Дозволяє показати:

- усі записи;
- лише записи за конкретною камерою.

### 7.3. Фільтр `Місце в ієрархії`

Дозволяє відфільтрувати записи за одним зі значень:

- `не визначено`
- `мужики`
- `козли`
- `блатні`
- `опущені`

### 7.4. Фільтр за датою звільнення

Два поля:

- `Дата звільнення з`
- `Дата звільнення по`

дозволяють обмежити список діапазоном дат звільнення.

Якщо для ув'язненого встановлено ознаку `Довічно`, такий запис не бере участі у фільтрації за датами звільнення.

### 7.5. Кнопка `Скинути фільтри`

Скидає:

- текст пошуку;
- фільтр камери;
- фільтр ієрархії;
- діапазон дат звільнення.

Після скидання знову відображається повний список.

### 7.6. Порожній результат

Якщо жоден запис не відповідає умовам пошуку або фільтрів:

- таблиця стає порожньою;
- відображається повідомлення `Записів не знайдено`.

## 8. Додавання нового запису

Вікно додавання відкривається:

- кнопкою `Додати`;
- через пункт меню;
- комбінацією `Ctrl+N`.

### 8.1. Поля форми

Форма містить такі поля.

#### Обов'язкові поля

- `Прізвище`
- `Ім'я`
- `Дата народження`
- `Стаття КК`
- `Термін покарання (років)` або прапорець `Довічно`
- `Дата взяття під варту`
- `Номер камери`

#### Необов'язкові поля

- `По батькові`
- `Місце в ієрархії`
- `Відомості про родичів`
- `Особливості характеру`

### 8.2. Автоматично обчислюване поле

Поле `Дата звільнення` обчислюється автоматично:

- якщо вказано строк у роках, дата звільнення = дата взяття під варту + строк;
- якщо встановлено прапорець `Довічно`, замість дати відображається текст `Довічно`.

### 8.3. Кнопки вікна

У нижній частині вікна доступні:

- `Зберегти`
- `Скасувати`

Також підтримуються:

- `Enter` - зберегти;
- `Esc` - закрити вікно без збереження.

## 9. Редагування запису

Редагування відкривається:

- кнопкою `Редагувати`;
- з меню;
- подвійним клацанням по рядку таблиці.

Вікно редагування повністю повторює форму додавання, але:

- усі поля вже заповнені поточними значеннями;
- заголовок вікна вказує, що виконується редагування;
- після збереження оновлюється наявний запис, а не створюється новий.

## 10. Видалення запису

Видалення виконується:

- кнопкою `Видалити`;
- через меню;
- клавішею `Delete`.

Перед видаленням програма показує підтвердження.

Користувач бачить питання:

`Видалити запис про [ПІБ]? Цю дію неможливо скасувати.`

Якщо користувач підтверджує видалення:

- запис видаляється зі списку;
- зміни зберігаються в `data.json`.

Якщо користувач відмовляється:

- видалення скасовується;
- список залишається без змін.

## 11. Валідація даних

Програма перевіряє коректність введення перед збереженням запису.

Якщо значення введено неправильно:

- поле виділяється червоною рамкою;
- під полем показується текст помилки;
- збереження не виконується, доки помилки не буде виправлено.

### 11.1. Правила перевірки полів

#### `Прізвище`

- обов'язкове;
- довжина від 1 до 100 символів.

#### `Ім'я`

- обов'язкове;
- довжина від 1 до 100 символів.

#### `По батькові`

- необов'язкове;
- до 100 символів.

#### `Дата народження`

- не може бути пізнішою за поточну дату;
- не може бути пізнішою за дату взяття під варту.

#### `Стаття КК`

- обов'язкове;
- до 50 символів.

#### `Термін покарання (років)`

- обов'язковий, якщо не встановлено прапорець `Довічно`;
- має бути цілим числом;
- допустимий діапазон: від 1 до 25.

#### `Дата взяття під варту`

- не може бути пізнішою за поточну дату;
- не може бути ранішою за дату народження.

#### `Номер камери`

- обов'язковий;
- має бути цілим числом;
- допустимий діапазон: від 1 до 999.

#### `Відомості про родичів`

- необов'язкові;
- до 500 символів.

#### `Особливості характеру`

- необов'язкові;
- до 500 символів.

## 12. Робота зі строком `Довічно`

Для довічного строку передбачено прапорець `Довічно`.

Якщо його встановлено:

- поле кількості років стає неактивним;
- строк у роках не потрібен;
- дата звільнення відображається як `Довічно`;
- такий запис коректно зберігається у файл.

## 13. Вікно статистики

Вікно статистики відкривається:

- кнопкою `Статистика`;
- через меню `Статистика`.

Воно призначене для отримання зведеної інформації за всіма записами.

### 13.1. Які дані показує статистика

Вікно містить:

- загальну кількість ув'язнених;
- розподіл за статтями;
- розподіл по камерах;
- список звільнень у поточному місяці;
- розподіл за ієрархічними статусами.

### 13.2. Блок `Загальна кількість ув'язнених`

Показує загальну кількість записів, що зберігаються в системі.

### 13.3. Таблиця `Розподіл за статтями КК`

Показує:

- статтю;
- кількість ув'язнених за цією статтею.

Таблиця сортується за спаданням кількості.

### 13.4. Таблиця `Розподіл по камерах`

Показує:

- номер камери;
- кількість осіб у камері;
- заповненість.

Для розрахунку заповненості у програмі прийнято єдину місткість:

- `4 особи на камеру`.

Приклад відображення:

- `3/4 (75%)`

### 13.5. Блок `Звільнення протягом поточного місяця`

Містить записи тих ув'язнених:

- у яких є звичайний строк, а не `Довічно`;
- дата звільнення потрапляє в поточний місяць.

Для кожного запису відображаються:

- ПІБ;
- дата звільнення.

### 13.6. Таблиця `Розподіл за місцем в ієрархії`

Показує:

- статус;
- кількість ув'язнених;
- відсоток від загальної кількості.

## 14. Зберігання даних

### 14.1. Де лежать дані

Файл даних:

- називається `data.json`;
- знаходиться поруч із виконуваним файлом програми.

Це було зроблено за твоєю вимогою, щоб файл лежав поруч із `.exe`, а не в `%AppData%`.

### 14.2. Коли відбувається збереження

Збереження виконується автоматично:

- після додавання запису;
- після редагування запису;
- після видалення запису.

### 14.3. Коли відбувається завантаження

Завантаження виконується:

- під час запуску головного вікна програми.

## 15. Структура даних ув'язненого

Кожен запис про ув'язненого містить такі дані:

- `Id` - унікальний ідентифікатор;
- `LastName` - прізвище;
- `FirstName` - ім'я;
- `MiddleName` - по батькові;
- `BirthDate` - дата народження;
- `CriminalArticle` - стаття КК;
- `SentenceYears` - строк у роках;
- `IsLifeSentence` - ознака довічного строку;
- `ArrestDate` - дата взяття під варту;
- `CellNumber` - номер камери;
- `HierarchyLevel` - положення в ієрархії;
- `RelativesInfo` - відомості про родичів;
- `CharacterNotes` - особливості характеру.

## 16. Архітектура проєкту

Проєкт організований за патерном `MVVM`.

### 16.1. Папка `Models`

Містить предметні моделі та допоміжні класи:

- `Prisoner`
- `HierarchyLevel`
- класи для відображення статистики та фільтрів

### 16.2. Папка `ViewModels`

Містить логіку інтерфейсу:

- `MainViewModel` - керування головним вікном, списком, фільтрами та діями;
- `EditPrisonerViewModel` - логіка форми додавання або редагування та валідація;
- `StatisticsViewModel` - підготовка статистичних даних.

### 16.3. Папка `Views`

Містить XAML-вікна:

- `MainWindow`
- `EditPrisonerWindow`
- `StatisticsWindow`

### 16.4. Папка `Services`

Містить роботу з даними:

- `IDataService`
- `JsonDataService`

### 16.5. Папка `Infrastructure`

Містить базові службові класи:

- `ObservableObject`
- `ViewModelBase`
- `RelayCommand`

Це забезпечує "чистий" варіант MVVM без зовнішніх бібліотек.

## 17. Типовий сценарій роботи користувача

Нижче наведено приклад звичайної роботи з програмою.

### Сценарій 1. Перегляд списку

1. Користувач запускає `PrisonApp`.
2. На екрані відкривається головне вікно.
3. У таблиці відображається список ув'язнених.
4. У рядку стану показується кількість записів.

### Сценарій 2. Додавання нового ув'язненого

1. Користувач натискає `Додати`.
2. Відкривається форма введення.
3. Користувач заповнює обов'язкові поля.
4. За потреби позначає `Довічно`.
5. Натискає `Зберегти`.
6. Запис з'являється у загальному списку.
7. Зміни зберігаються в `data.json`.

### Сценарій 3. Редагування запису

1. Користувач вибирає рядок у таблиці.
2. Натискає `Редагувати` або двічі клацає по запису.
3. Змінює потрібні дані.
4. Натискає `Зберегти`.
5. Таблиця оновлюється, зміни зберігаються.

### Сценарій 4. Пошук і фільтрація

1. Користувач вводить текст у поле `Пошук`.
2. За потреби доповнює фільтри по камері, ієрархії та даті.
3. Список перебудовується одразу після зміни параметрів.
4. Унизу відображається кількість знайдених записів.

### Сценарій 5. Перегляд статистики

1. Користувач натискає `Статистика`.
2. Відкривається окреме вікно.
3. Користувач переглядає агреговані зведення.
4. Після перегляду закриває вікно кнопкою `Закрити`.

## 18. Що важливо пам'ятати під час використання

- програма зберігає дані локально;
- резервне копіювання виконується копіюванням файлу `data.json`;
- видалення запису є незворотним у межах поточної версії;
- зміни зберігаються одразу після дії, окремої кнопки `Зберегти базу` немає;
- при пошкодженні `data.json` логіка завантаження може створити нові демонстраційні дані, якщо файл виявиться порожнім або невалідним.

## 19. Обмеження поточної версії

На поточному етапі в програмі немає:

- розмежування прав доступу;
- авторизації користувачів;
- імпорту або експорту в Excel чи PDF;
- друку звітів;
- бази даних;
- мережевого режиму роботи кількох операторів.

Ці функції можна додати пізніше як розвиток проєкту.

## 20. Підсумок

`PrisonApp` реалізує повний базовий цикл роботи з довідником ув'язнених:

- створення записів;
- редагування;
- видалення;
- пошук;
